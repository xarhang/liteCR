# Public documentation website

This page-specific direction applies to tools/docs and the GitHub Pages site, not the clinical application workspace.

Use the existing semantic tokens from packages/design-system/src/tokens.css, local system fonts and a calm teal accent. The homepage explains the product and routes visitors to tasks; documentation pages prioritize a readable article, grouped navigation and a table of contents. A public overview hero is appropriate here; the workspace's prohibition on conversion heroes still applies inside the registry application.

Keep the site static, with no analytics, remote fonts, login controls or patient-data forms. Use native details elements for FAQs and collapsed mobile navigation. At narrow widths, stack the overview sections and keep code/table scrolling inside their containers. Retain visible keyboard focus, skip links, reduced-motion support and dark-mode tokens.

All example identities are invented. Label the workflow illustration as conceptual; do not present it as an actual application screenshot, match result or accuracy measurement. Make setup prerequisites and Beta limits easy to find.
